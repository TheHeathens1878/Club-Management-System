# P4.3 — safeguarding concerns (SG-3), SG-6 tier 2, audit_read

`supabase/migrations/20260823180000_safeguarding_concerns.sql` · Linear TH1-30

## SG-3 as written — privileges first

- `safeguarding_concerns` and `safeguarding_concern_notes`: **ALL privileges
  revoked from anon, authenticated and `service_role`**, and the ref sequence.
  `direct_select_on_concerns_throws_for_service_role` is the test that the
  earlier FORCE-RLS design would have failed.
- Every read/write is a SECURITY DEFINER accessor writing its SG-7 row before
  returning, **including when it returns zero rows** — so an unauthorised
  `read_concerns()` returns nothing *and logs the attempt* (a raise would roll
  the audit row back with it): `report_concern`, `my_concern_receipts`
  (reporter's narrow receipt, D3), `read_concerns` (lead + club_admin,
  excluding concerns that name the caller — even a club_admin),
  `update_concern` (lead: status/severity/legal_hold), `add_concern_note` and
  `read_concern_notes` (lead only — club_admin reads the concern, never the
  case notes).
- SG-2 on both tables; narrative/ref/reporter immutable; `SC-YYYY-NNNN` refs.
- RLS enabled **and forced** with the same write model, as layer 4.
- `audit_log` gains a guard refusing `safeguarding.concern.*` rows whose
  `detail` carries `narrative`/`body`/`note` (SG-7's content rule, testable).

## SG-8

`people.legal_hold` is lead-only and audited; pseudonymising a person named in
an open concern or under hold is refused.

## SG-6 tier 2

`certification_nudges` (sent 90/30/7 per certification, never re-sent),
`due_certification_nudges()`, `mark_certification_nudged()` (service_role —
the `safeguarding-nudges` Edge Function sends via P4.4's `enqueue_message`),
`person_compliance_status()` valid/expiring/expired/missing,
`compliance_report()` — the nightly "non-compliant and still assigned" list.

## audit_read

Re-expressed: `safeguarding.%` and `messaging.%` rows readable by
`club_admin` + `safeguarding_lead` only; everything else by `club_admin` or
legacy committee.
