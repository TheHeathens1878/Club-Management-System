# P3.4 — Neon cutover: go/no-go checklist and abort procedure

Written before any window, as PLAN §11 requires. Runs only after P3.3's
rehearsal and reconciliation pass cleanly (PLAN §3 Q5).

## Pre-window (the day before)

- [ ] P3.3 rehearsal on a preview branch: restore → transform → reconcile, all
      checks ok; numbers recorded here: users ___, teams ___, pitches ___,
      bookings ___, payments £___.
- [ ] P3.2 dry run: `{created, refused_by_sg10, non_bcrypt}` recorded; Adam
      has chosen Strategy A or B.
- [ ] Comms email approved; recipient list = legacy users with a live
      booking or a team link in the last 12 months (others get a lighter note).
- [ ] Vercel: new project for `apps/web` is deployed and smoke-tested on its
      `*.vercel.app` URL (P1.6 cutover done first — same evening is fine).
- [ ] Stripe (if the legacy app takes card payments): new webhook endpoint
      `/functions/v1/stripe-webhook` registered in **test** mode and exercised;
      live endpoint created but disabled until step 6.
- [ ] DNS TTL on `coaches.` and `membership.` lowered to 300 s.
- [ ] Quiet weekday evening chosen; committee told; the hostnames' banner
      ("read-only from 20:00 tonight") live on the legacy app if possible.

## Window (target ≤ 45 minutes)

1. **Freeze Neon writes** — in Neon: set the app's role to read-only
   (`ALTER ROLE app_user NOLOGIN` or revoke INSERT/UPDATE/DELETE), or in Vercel
   set the legacy project's `DATABASE_URL` to the read-only role and redeploy.
   Confirm a test booking on the legacy app fails.
2. **Final dump** — `pg_dump` Neon → `neon_legacy` schema on prod (the same
   script as the rehearsal). Record row counts.
3. **Transform + reconcile** — run P3.3's transform functions on prod;
   `reconcile_neon()` must return all-ok. **Any failure → ABORT (below).**
4. **Auth import** — P3.2 import (A or B). Record counts.
5. **Repoint** — move `coaches.aomsportsclub.co.uk` and
   `membership.aomsportsclub.co.uk` to the new Vercel project (redirect both to
   the new app's `/pitches` and `/teams` routes, or serve the new app on them).
6. **Stripe** — enable the live webhook endpoint; disable the legacy one.
7. **Smoke test** — sign in as an imported user; see their team(s) and
   upcoming pitch bookings; create and cancel a test booking; `/recruitment`
   public page renders; a reset-password email arrives (Strategy B).
8. **Send comms** — through `enqueue_message` (logged).
9. **Neon read-only stays on** for 30 days (P3.5).

## Abort procedure

- Before step 5: nothing user-visible has changed. Re-enable Neon writes
  (reverse step 1). Leave `neon_legacy` in place; drop the rows the transform
  inserted using their `legacy_neon_*` ids (`delete … where legacy_neon_id is
  not null`) — the same shape as P1.6's rollback.
- After step 5: repoint DNS back to the legacy Vercel project, re-enable Neon
  writes, disable the new Stripe endpoint and re-enable the legacy one. Any
  booking made in the new app during the window is exported and re-keyed by
  hand (expected count: near zero on a quiet evening).
- Go/no-go owner: Adam. Claude executes and records every step's output in
  DECISIONS.md.
