## Decisions

1. **`certifications` and `certification_exemptions` are created here, not in
   P4.3.** SG-6 names P2.1 as the implementer of the tier-1 triggers, and a
   trigger that evaluates a table which does not exist either fails closed
   (no coach could ever join a youth team until Phase 4) or is a stub (the
   prohibited state is reachable for weeks). Neither is acceptable, so the
   minimum real tables come forward. P4.3 adds the 90/30/7 nudges, the
   nightly report and the compliance views, and may extend the tables.
2. **The required set is fixed: fa_dbs + safeguarding_children** (C3).
   Configurability is a P4.3 question; a constant in one function is the
   cheapest thing to change.
3. **No automatic `coach` app role from a coach membership.** §1.3's app
   role is an app-wide grant an administrator makes; RLS here keys on the
   live membership (`is_team_staff`). DECISIONS.md.
4. **RLS on `team_memberships`:** club_admin + safeguarding_lead read all;
   club_admin writes; team staff (live child-facing membership) read their
   team; self-read; an active guardian reads a minor child's rows. Coaches
   cannot read `certifications` of others — compliance is evaluated by the
   definer functions, never by a coach's own SELECT.
5. A BEFORE trigger fires before a policy's WITH CHECK, so a `club_admin`
   attempting to grant an exemption gets the guard's `P0001`, not `42501`.
   Both layers refuse; the test asserts the one that fires first.
