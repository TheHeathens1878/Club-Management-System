# P1.6 cutover — `20260824100000_legacy_room_tables_to_views.sql`

Step 3 of `docs/runbooks/P1.6-cutover.md`. Pushed to prod only inside the
cutover window, after the old Vercel project is paused and the re-sync +
reconcile have passed.

## What it does

1. Renames `room_bookings`, `booking_payments`, `booking_emails`,
   `function_rooms` to `*_legacy`; revokes all privileges from `anon` and
   `authenticated` (`service_role` keeps SELECT for the 30-day check). Legacy
   RLS policies and indexes travel with the renamed tables.
2. Creates `security_invoker` views under the four old names over
   `resources` / `bookings` / `payments` / `booking_comms`, restricted to rows
   carrying a `legacy_*_id`, with exactly the legacy column set (asserted by
   test). `room_bookings.amount_pence` is served by `total_pence`. The views
   are joins with expressions, so they are not updatable: any straggling
   writer fails; readers keep working.
3. Re-creates `migrate_room_bookings()` / `reconcile_room_bookings()` with
   bodies identical to `20260823110000` except that the four legacy names are
   `*_legacy`, so the abort path and the 30-day check remain truthful.
4. One `migration.cutover` audit row.

Nothing is dropped (PLAN §2.5). The `*_legacy` tables are decommissioned in a
later migration with Adam's sign-off in DECISIONS.md.
