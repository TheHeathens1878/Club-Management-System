# P4.1 — subs & payments: plans, subscriptions, the ledger, Stripe events

`supabase/migrations/20260823170000_subscriptions.sql` · Linear TH1-28 ·
Edge Function `stripe-webhook` (supabase/functions)

| Object | Notes |
|---|---|
| `subscription_plans` | per season, optional team; `amount_pence`; `billing` one_off/monthly/annual (+`instalments`); Stripe product/price ids once created; `active`. |
| `subscriptions` | player × plan, paid by `payer_person_id` — **an adult with a known DOB who is the player or an active guardian** (guard); `amount_due_pence` snapshotted from the plan; status pending → active → past_due/cancelled/completed; Stripe ids; payer may create (pending) and cancel their own pending; status otherwise `club_admin` or `service_role` (the webhook). |
| `payments` (ledger) | `booking_id` now nullable; `subscription_id`; `kind` derived by trigger (hire/subscription/other); `stripe_*` ids; `refunded_pence`; at most one link; unique `stripe_payment_intent_id`. Existing hire rows untouched. |
| `stripe_events` | every webhook delivery by event id — insert-first idempotency. `service_role` only. |
| `subscription_arrears` | security_invoker view: due / paid (net of refunds) / outstanding per live subscription; names via `display_name()` (a SECURITY DEFINER helper that reveals a name only to self, guardians, the person's team staff, or admins). |
| `display_name(person_id)` | reusable: the reason a coach can see "outstanding £90 — Kid Subs" without a `people` read grant. |

RLS: plans readable by anyone logged in (active) and written by `club_admin`;
subscriptions readable by the player, payer, guardians of a minor player, the
plan's team staff, admins; `payments_subscription_read` extends P1.5's
policies the same way. `stripe_events` has no authenticated policy.

Tests: `supabase/tests/subscriptions.test.sql` — 43: guard (minor payer,
non-guardian payer, self-only sign-up, pending start, cancel own, immutability),
webhook lifecycle as `service_role` (activate, event idempotency, payment with
unique intent), ledger checks, arrears maths incl. refunds, RLS matrix.

Stripe: the Edge Function verifies the signature, inserts the event
(`on conflict do nothing` → skip if already processed), and on
`checkout.session.completed` / `invoice.paid` / `customer.subscription.*`
updates `subscriptions` and inserts `payments`. Test-mode keys live in Supabase
secrets (`STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`); nothing in the repo.
