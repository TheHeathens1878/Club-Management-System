# P2.2 — registrations, SG-5 photo-consent types

`supabase/migrations/20260823130000_registrations.sql` · Linear TH1-19 ·
branch `phase-2/p2.2-registrations` · spec: `docs/specs/P2.2-registration-flow.md`

## What it does

- `consent_type` gains `photo_team_album`, `photo_club_website`,
  `photo_social_media`, `photo_press` (SG-5's four separate decisions, D4).
- `registration_status` (pending / approved / rejected / withdrawn) and
  `registrations` (person × season, optional team, `form jsonb`,
  `form_version`, submitted/decided stamps), partial unique on live rows.
- `registrations_guard()`: who may submit (adult self / active guardian of a
  minor / club_admin / service_role); status machine; decisions admin-only;
  withdrawal by subject or guardian; identity immutable; `decided_*` stamped
  by the trigger; **approval with a team creates the player membership, so
  P2.1's SG-6 guard runs at approval time and a non-compliant team fails the
  approval** naming the coach.
- `registrations_audit()`: `registration.submitted` / `registration.decided`,
  never the form.
- RLS: admin read (club_admin + safeguarding_lead) / insert / update
  (club_admin); self read / insert / withdraw; guardian read / insert /
  withdraw via `is_active_guardian_of()`. **Coaches read nothing** — the form
  is medical data.

## Decisions

1. **Photo consent reuses `guardian_consents`** rather than a `photo_consents`
   table. SAFEGUARDING §4's P1.7 block says so in terms ("P2.2 adds the SG-5
   photo-consent values by `alter type … add value`"); the older checklist
   line predates P1.7 settling the consent model. One grant guard, one
   immutability rule, one audit trigger, one `has_active_consent()` for P4.5.
   The SG-7 vocabulary for photo consent is therefore
   `safeguarding.consent.granted` / `.revoked` (P1.7's), not the proposed
   `safeguarding.consent.change` — recorded for P4.3 to fix the table.
2. **Per-season scoping is `expires_at`** (set to the season's end at
   capture). `has_active_consent()` already honours it; D12 stays open for
   the two P1.7 types, which keep NULL.
3. A trigger fires before RLS WITH CHECK, so "wrong person submits" surfaces
   as the guard's `P0001` rather than `42501`; both layers refuse.
