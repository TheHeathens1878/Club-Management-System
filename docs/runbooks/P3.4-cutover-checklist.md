# P3.4 — Neon cutover: go/no-go checklist and abort procedure

Written before any window, as PLAN §11 requires. Runs only after P3.3's
rehearsal and reconciliation pass cleanly (PLAN §3 Q5). Updated 2026-08-23
against the built import (`20260824000000_neon_import.sql`, MIGRATION_MAP
§4–§5): there are **no payments or Stripe** in the Neon app, so those steps
are gone.

## Pre-window (the day before)

- [ ] P3.3 rehearsal on a preview branch: restore → `migrate_neon()` →
      `reconcile_neon()` all ok; numbers recorded in PLAN P3.3.
- [ ] P3.2 dry run on the same branch: `neon-auth-import.mjs` created ___
      users, ___ failed (expected 52 / 0).
- [ ] **A `safeguarding_lead` is appointed** in prod (`person_roles`) — without
      one no imported coach can be activated (D-P3-2).
- [ ] Comms email (P3.2 runbook) approved; recipients = the 52 imported logins.
- [ ] P1.6 Vercel cutover done: the new web app serves the club hostnames or
      its own URL, and `/complete-profile` loads.
- [ ] `.env.neon` holds the **owner** Neon URL for the freeze step (the
      read-only role cannot revoke privileges) — or Adam performs step 1 in the
      Neon console himself.
- [ ] DNS TTL on `coaches.` and `membership.` lowered to 300 s.
- [ ] Quiet weekday evening chosen; committee told.

## Window (target ≤ 45 minutes)

1. **Freeze Neon writes** — Neon console → SQL editor (owner):
   `revoke insert, update, delete on all tables in schema public from <app role>`
   (the role in Vercel's `DATABASE_URL`), or set the legacy Vercel project's
   `DATABASE_URL` to the `claude_ro` role and redeploy. Confirm a test booking
   on the legacy app fails.
2. **Final dump → prod** — `TARGET_DB_URL=<prod pooler URL> bash
   scripts/neon-restore.sh` (drops the stub `neon_legacy`, restores the real
   one). Record the row counts it prints; `User` must be 61 (or whatever the
   day's count is), `Booking` the live count.
3. **Transform + reconcile** — as service_role / owner on prod:
   `select * from public.migrate_neon();` then
   `select * from public.reconcile_neon() where not ok;` → **must be empty.
   Any row → ABORT (below).** Record the migrate counts.
4. **Auth import** — `node apps/web/scripts/neon-auth-import.mjs` with prod
   `SUPABASE_URL`/`SUPABASE_SERVICE_ROLE_KEY`. Record created/failed; a
   non-zero failed count is a **no-go for step 5** unless every failure is an
   already-known merge case.
5. **Repoint** — `coaches.aomsportsclub.co.uk` and
   `membership.aomsportsclub.co.uk` → the new Vercel project (serve the new
   app; `/recruitment` → `/waiting-list` redirect).
6. **Smoke test** — sign in as an imported coach with their **old** password;
   land on `/complete-profile`; enter DOB; see the team(s) (exemption granted,
   `audit_log` shows `safeguarding.certification.exemption`); see upcoming
   pitch bookings on `/pitches`; create and cancel a test booking; the public
   waiting-list form submits (`submit_waiting_list_entry`). Sign in as a
   club_admin: waiting list visible with notes.
7. **Send comms** — through `enqueue_message` (logged, suppressions respected).
8. **Neon read-only stays on** for 30 days (P3.5). `.env.neon` stays until
   P3.5, then is deleted.

## Abort procedure

- Before step 5: nothing user-visible has changed. Reverse step 1. Leave
  `neon_legacy` in place. Remove what the transform inserted, in dependency
  order, by legacy key — as the owner:
  `delete from bookings where legacy_neon_ref is not null;`
  `delete from team_memberships where notes like 'imported from Neon%';`
  `delete from certification_exemptions where reason like 'Neon pitch-booking import%';`
  `delete from guardianships where notes like 'imported from Neon%';`
  `update person_roles set revoked_at = now() where notes like 'imported from Neon%' and revoked_at is null;`
  `delete from waiting_list_notes; delete from waiting_list_entries where source in ('import','team_application'); delete from waiting_list_access; delete from waiting_list_age_groups;`
  `delete from neon_import_pending;`
  `delete from resources where legacy_neon_pitch_id is not null; delete from teams where legacy_neon_team_id is not null;`
  `update people set legacy_neon_user_id = null where id in (select person_id from profiles);`
  `update people set deleted_at = now() where legacy_neon_user_id is not null;`
  Auth users created in step 4: delete through the admin API (the list is the
  script's output).
- After step 5: repoint DNS back to the legacy Vercel project, reverse step 1,
  then the list above. Any booking made in the new app during the window is
  exported and re-keyed by hand (expected count: near zero on a quiet evening).
- Go/no-go owner: Adam. Claude executes and records every step's output in
  DECISIONS.md.
