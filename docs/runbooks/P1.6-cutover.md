# P1.6 cutover runbook — function-room app onto the unified tables

The P1.6 migration (`20260823110000_migrate_room_data.sql`) copies the legacy
function-room data into `resources` / `bookings` / `payments` / `booking_comms`
and leaves the legacy tables live, because the public site still deploys from
the old `AoM-Sports-Club-Function-Room` repo (P0.4's Vercel repoint was
deferred). Until the repoint, the old app keeps writing to the legacy tables
and the unified copy drifts behind them. This runbook is the step that ends
that: it needs Vercel credentials, which Claude does not hold, so **Adam runs
it** (or sits with Claude while it runs).

Everything below is idempotent and re-runnable. Nothing is dropped (PLAN §2.5).

## Window (≈15 minutes)

1. **Freeze legacy writes.** *(2026-08-23: optional — `20260824100000` performs the
   final sync, the reconcile gate and the rename in one transaction, so the
   rename itself is the freeze: the old site keeps reading through the views and
   any write it attempts fails. Pausing is only needed if you want the old
   hostname dark rather than read-only.)* Easiest: in the old Vercel project, set the
   environment variable `SUPABASE_SERVICE_ROLE_KEY` to an invalid value and
   redeploy (every legacy write goes through the service-role client), or
   simply pause the old project. Confirm the old site's booking form now errors.
2. **Re-sync** *(now done by section 0 of the migration; run by hand only to preview)*. As `service_role` (Supabase SQL editor with the service key, or
   `psql` as `postgres`):
   ```sql
   select * from public.migrate_room_bookings();
   select * from public.reconcile_room_bookings() where not ok;  -- must be empty
   ```
   The first call upserts every legacy row changed since the migration ran and
   removes unified copies of legacy rows the old app hard-deleted; it writes one
   `migration.backfill` audit row. If the second query returns anything, STOP —
   unfreeze (step 1 reversed) and investigate; nothing has been renamed yet.
3. **Rename the legacy tables and put read-only views in their place.**
   Written and rehearsed 2026-08-23 as `supabase/migrations/20260824100000_legacy_room_tables_to_views.sql`
   (`docs/migrations/P1.6-cutover-views.md`). Push it now: `npx supabase db push --linked`.
   The sketch it was built from:
   ```sql
   -- Legacy function-room tables → *_legacy, with read-only views under the old
   -- names so any straggling reader still works and any straggling writer fails.
   alter table public.room_bookings    rename to room_bookings_legacy;
   alter table public.booking_payments rename to booking_payments_legacy;
   alter table public.booking_emails   rename to booking_emails_legacy;
   alter table public.function_rooms   rename to function_rooms_legacy;

   create view public.function_rooms with (security_invoker = true) as
     select legacy_function_room_id as id, name, description, capacity,
            price_pence_per_hour, price_pence_half_day, price_pence_full_day,
            active, sort_order, created_at, amenities as resources,
            price_pence_fixed, price_note, information, extras_config,
            standard_price_pence, standard_hours, extra_hour_pence
     from public.resources where legacy_function_room_id is not null;

   create view public.room_bookings with (security_invoker = true) as
     select b.legacy_room_booking_id as id, r.legacy_function_room_id as room_id,
            (b.starts_at at time zone 'Europe/London')::date as date,
            (b.starts_at at time zone 'Europe/London')::time as start_time,
            (b.ends_at   at time zone 'Europe/London')::time as end_time,
            b.booker_name, b.booker_email, b.booker_phone, b.occasion, b.estimated_guests,
            b.notes, b.status::text, b.amount_pence_compat as amount_pence, ...
     -- Generate the full column list from the baseline at cutover time; every
     -- legacy column except `amount_pence` has a same-named unified column.
     from public.bookings b join public.resources r on r.id = b.resource_id
     where b.legacy_room_booking_id is not null;
   -- booking_payments / booking_emails views likewise, over payments / booking_comms.

   revoke all on public.room_bookings_legacy, public.booking_payments_legacy,
                 public.booking_emails_legacy, public.function_rooms_legacy
     from anon, authenticated;   -- service_role keeps read for the 30-day check
   ```
   Note `room_bookings.amount_pence` has no unified equivalent by design (the
   app derives it); the view can expose `total_pence` under that name if any
   reader still wants it. Legacy RLS policies travel with the renamed tables.
4. **Repoint.** In Vercel, move `roombooking.aomsportsclub.co.uk` to the new
   project. Update `NEXT_PUBLIC_SITE_URL` if it was the preview URL. Confirm the
   SumUp webhook URL and the Google Calendar redirect URI still resolve (same
   hostname, so they should).
5. **Smoke test** on the live hostname: public `/book` shows rooms and
   availability; a test booking lands in `public.bookings` with
   `legacy_room_booking_id` NULL and the right Europe/London times; staff list,
   detail, confirm, record payment, cancel; portal shows the booker's bookings;
   cron endpoint responds 200 with `CRON_SECRET`.
6. **Record.** DECISIONS.md row; PLAN.md P1.6 → ☑; Linear TH1-15 → Done.

## Abort

Before step 3: unfreeze the old project (restore the variable / unpause). The
unified copy is only a copy; nothing else changed.

After step 3, before step 4: reverse the renames (`drop view …; alter table
… rename to …`) in one transaction and unfreeze. Rows written to the unified
tables in between are native rows and survive; run `migrate_room_bookings()`
again later.

After step 4: repoint the domain back and do the above. Anything the new app
wrote in the window stays in the unified tables.

## After 30 clean days

Drop the four `*_legacy` tables in a migration with Adam's sign-off recorded
in DECISIONS.md (PLAN §2.5 — this is the explicit decommission task), and
delete `migrate_room_bookings()` / `reconcile_room_bookings()` with them.
