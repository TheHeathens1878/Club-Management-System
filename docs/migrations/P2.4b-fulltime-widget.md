# Full-Time widget import via pg_net (2026-08-24)

Migrations: `20260824130000_fulltime_widget.sql` (PR #43: `widget_code`),
`20260824190000_fulltime_pgnet_fetch.sql` (this PR).

## What changed and why

P2.4's importer scraped Full-Time's fixtures page and was refused by Cloudflare
from every cloud IP, which left the club running a script on a PC
(`docs/runbooks/fulltime-import.md`, previous version). Two findings on
2026-08-23 changed that:

1. **The widget endpoint.** Full-Time's "add to your website" snippet loads
   `https://fulltime.thefa.com/js/cs1.html?cs=<lrcode>` — one JavaScript
   statement whose string is the team's fixtures *and results* for the season,
   every row linked by the same `displayFixture.html?id=` the page scraper keys
   on. Team-scoped, so no team-name matching against a division page.
2. **Who Cloudflare refuses.** Tested from the Supabase project itself
   (`net._http_response` ids 300–312 on 2026-08-23): Deno `fetch()` in an Edge
   Function → 403 for both the widget and the page, with exactly the headers
   that get pg_net (libcurl) a 200 for both. Cloudflare is fingerprinting the
   TLS client. The headers that matter for libcurl are a desktop `User-Agent`
   **and** `Accept-Language: en-GB,en;q=0.9` (UA alone → 403).

So the request is made by Postgres and the Edge Function collects the body.

## Schema

- `team_fulltime_links.widget_code text` (6–12 digits; PR #43). `league_id` and
  `ft_season_id` are now nullable; `team_fulltime_links_has_source` requires a
  widget code or league+season.
- `fulltime_http_requests` (RLS, no policies): every pg_net id issued by
  `fulltime_http_get`, so `fulltime_http_result` can never return the response
  to some other pg_net call (e.g. the Edge Function invocations, whose requests
  carry the service-role key).
- `fulltime_http_get(p_url)`: club_admin or service role; `https://fulltime.thefa.com/`
  only; adds the UA/Accept/Accept-Language headers; 20 s timeout; returns the
  pg_net id. `fulltime_http_result(p_id)`: `done=false` until the worker has
  written the response; errors for ids it did not issue.
- `fulltime_import_targets()` gains `widget_code`.
- `fixture_import_runs.trigger`: `manual_widget` replaces the never-used
  `browser_widget`.

Rollback is documented at the top of the migration.

## Code

- `packages/fulltime/src/pgnet.ts` — `fetchViaPgNet(client, url)` polls the two
  RPCs and returns the same `FullTimeResponse` shape as `fetchFullTimePage`, so
  classify → parse → `import_fixtures()` is unchanged downstream. Never throws.
- `packages/fulltime/src/widget.ts` — `widgetCodeFrom`, `widgetUrl`,
  `widgetHtmlFrom` (JS-string unescape), `parseWidgetHtml`, `widgetTeamName`
  (the team in every row — the team the widget was generated for).
- `supabase/functions/fulltime-import` — widget first, page URL fallback, fetch
  via pg_net. Trigger `manual_widget`/`manual_url` for on-demand runs.
- `/teams/[id]` link panel — paste snippet/code/URL → preview (team name read
  off the widget; venue and score columns) → save → **Import now**.
- `apps/web/scripts/fulltime-local-import.mjs` — kept as the fallback; widget-aware.

## Follow-up: the nightly run (20260824193000_fulltime_prefetch.sql)

First real run through the cron path hung: pg_net serves its queue in serial
batches, so a fetch queued by the function while pg_net is still waiting on
`invoke_edge_function` cannot be served until that invocation ends (response
335 queued behind 334, served the moment 334 returned). Direct calls — the
team page's **Import now** — were fine: 20 fixtures in 1.1 s.

So the nightly job is two cron steps: 03:12 UTC `fulltime_prefetch()` queues
one fetch per enabled link from SQL (`fulltime_prefetches` records the ids;
`fulltime_source_url()` picks widget vs page); 03:15 UTC the Edge Function
runs as before and reads each team's response through `fulltime_prefetched()`
+ `fetchViaPgNet({ requestId })`, falling back to a live fetch when no fresh
prefetch exists. The 5 s inter-team rate limit now applies to live fetches
only. `fulltime-import` also moved to the shared `requireServiceRole` /
`userClient` helpers (it was 401 for the gateway-verified service JWT, the
issue PR #39 fixed for the other functions).

## Follow-up: club-wide widgets (20260824195000_fulltime_club_widgets.sql)

Full-Time also generates *club* widgets — one code for every team's upcoming
fixtures (five-cell rows `type | home | v | away | venue`, no score columns)
and a second for the club's results. Two codes in `site_settings`
(`fulltime_club_fixtures_code` / `fulltime_club_results_code`, saved from the
new **Teams → Club Full-Time widgets** card) feed every active team that has
no per-team link; widget names are matched onto team names by suffix
(`matchClubTeam`), ambiguous or unknown names are left alone, and the preview
flags club-side names that match no configured team.

`parseWidgetHtml` became a cell classifier (7-cell team rows, 5-cell club
rows, single-cell `3 - 1` scores, bare "Postponed" group headings — rows under
one have no date and are skipped with a single warning; "No Results" is
benign). The prefetch is per URL now (`fulltime_prefetches` re-keyed on the
pg_net request id, `fulltime_prefetched_url`), so a club URL is fetched once
however many teams it feeds.
