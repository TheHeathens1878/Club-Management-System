## Division of labour

| Layer | Responsibility |
|---|---|
| `packages/fulltime` | Pure TypeScript, no network in tests: `parseFullTimeUrl`, `parseFixturesPage`, `fixturesForTeam`, `stableExternalRef`, `parseCsvFixtures`, `classifyResponse` (`ok`/`challenge`/`not_found`/`error`), `fetchFullTimePage` with a desktop UA and a `RateLimiter`. Recorded-HTML fixtures from real pages (2026-08-23) plus a synthetic fixtures table. |
| `import_fixtures(team, season, fixtures jsonb, trigger, url, warnings)` | The one place an import *means* something: upsert by `(team_id, external_ref)`; a known ref with changed kickoff/status/scores/opponent/competition/venue is an UPDATE (reschedules and postponements never duplicate; results land after matches); unchanged refs get `last_seen_at`; refs absent from the page are left alone (a filtered page is not a cancellation); `source = 'manual'` rows are never touched. Writes a `fixture_import_runs` row and mirrors the outcome onto `team_fulltime_links.last_import_*`. `club_admin` or `service_role`. |
| `record_fixture_import_failure(team, trigger, status, url, error)` | For `error`/`challenge`/`skipped`: run row, link status, and a `fixtures.import_failed` audit row — the hook "alert admin" hangs on (surfaced on the teams screen now; routed as a notification by P4.2/P4.4). |
| `fulltime_import_targets()` | `service_role` only: enabled links × active teams × the current season. |
| Edge Function `fulltime-import` | Nightly via `pg_cron` + `pg_net`: for each target, fetch → classify → parse → `fixturesForTeam` → `import_fixtures`, with `RateLimiter` between teams; a `challenge` or error calls `record_fixture_import_failure` and moves on. Also callable on demand with `{ team_id }`. |
| Manual fallback (teams screen) | Paste a Full-Time URL (fetched server-side with the same parser, `manual_url`) or a CSV (`manual_csv`) → preview → `import_fixtures`. Works with the scheduled importer disabled. |

## Why the database owns the reconcile rule

The scheduled path and the manual path would otherwise each carry a copy of
"what does a known external_ref with a new kickoff mean", and they would
drift. One SECURITY DEFINER function, tested in pgTAP, is the rule.

## Cloudflare

Verified on 2026-08-23: the site answers a desktop browser UA for a few
requests, then serves a "Just a moment…" challenge (HTTP 200) and a 403 to
non-browser fetchers. The importer therefore spaces requests, classifies
every response, records `challenge` rather than retrying, and the manual
fallback is a first-class path, not an afterthought. Q2's "monitor for
breakage" is the `fixture_import_runs` table and the audit row.

## Tests

`supabase/tests/fulltime_import.test.sql` — 30 assertions: insert; repeat run
reconciles with no duplicates; reschedule + postponement + result as updates;
absence is not cancellation; manual rows untouched (incl. one carrying an
imported ref); payload validation (array, externalRef, unknown status, lone
score dropped); failure recording with audit; coach refused, admin allowed,
runs visible to admins only. Parser: vitest in `packages/fulltime`.
