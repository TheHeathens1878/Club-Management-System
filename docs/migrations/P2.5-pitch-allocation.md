# P2.5 — pitch allocation

`supabase/migrations/20260823160000_pitch_allocation.sql` · Linear TH1-22 ·
branch `phase-2/p2.5-pitch-allocation`

## What it does

| Object | Notes |
|---|---|
| `fixtures.booking_id` (unique → `bookings`), `fixtures.duration_minutes` (default 90), `fixtures.allocation_conflict` | The link, the booked length, and the flag an admin sees when a reschedule could not move the booking. |
| `bookings.fixture_id` (unique → `fixtures`) | Back-link so booking screens can label a slot "U13s v Angel FC". |
| `allocate_fixture(fixture, pitch, pre?, post?)` | SECURITY DEFINER, `club_admin` (or `service_role`). Home, scheduled fixtures only; pitch must be an active non-room resource. Creates or **moves** the linked booking (kind `fixture`, status `confirmed`, booker = the team, buffers from the pitch's defaults unless given). Conflicts are reported by name (`Hirer 16/09 11:00–13:00 (hire)`) as SQLSTATE `23P01` and nothing is written — `bookings_no_overlap` remains the arbiter behind it. |
| `unallocate_fixture(fixture)` | Cancels the booking (history kept) and clears link + venue. |
| `fixtures_sync_booking()` AFTER UPDATE OF kickoff_at, status, duration_minutes | A reschedule **moves** the linked booking; a clash **flags** (`allocation_conflict = true`, `fixtures.allocation_conflict` audit row) and leaves the booking where it was — never a double booking. Postponed/cancelled/abandoned frees the pitch; back to scheduled re-books with the same rules. |
| `bookings_fixture_guard()` | A linked fixture booking cannot be cancelled, moved or deleted directly — change the fixture or use the two functions — so the link never dangles. The functions bypass it with a transaction-local GUC they reset immediately. |
| `unallocated_home_fixtures` (security_invoker view), `pitch_grid(from, to)` | The admin dashboard's reads: upcoming home fixtures with no slot (or a flagged one); every live booking per pitch in a window, labelled. |

## Decisions

- The fixture is the master. Pitch time follows the fixture, not the other
  way round; importer reschedules (P2.4) therefore propagate through the
  ordinary UPDATE trigger without the importer knowing bookings exist.
- Flag, don't fail, on reschedule. An importer run must not abort because one
  pitch is taken; the admin gets a named conflict to resolve (the fixture
  reappears in the unallocated view).
